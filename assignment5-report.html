기존 프로젝트에 작은 기능을 개선하고, 서로 다른 AI 작업 세션이 저장소와 인수인계 문서만으로 같은 작업을 이어서 수행할 수 있는지 확인했다.

1. 프로젝트와 개선 목표

대상 프로젝트: card-studio

개선 목표: 템플릿 이름 중복 저장 방지

템플릿 이름을 저장하거나 편집할 때 동일한 이름이 중복으로 등록되지 않도록 개선했다.

  • 이름 앞뒤 공백 제거 후 비교
  • 빈 문자열 및 공백만 입력된 이름 저장 방지
  • 동일한 이름의 중복 저장 방지
  • 편집 시 다른 템플릿과 동일한 이름으로 변경 방지
  • 영문 대소문자는 구분
10/10 최종 고정 검사 통과
30분 공통 작업 시간 상한
10회 공통 요청·호출 상한

2. 작업 순서

기준선 0dce09c
AI A 작업 e31be38
인수인계 0770c52
AI B 작업 2ecd143
작업 순서는 A 시작 → A 종료/상태 보존 → 인수인계 → B 시작 → B 종료 로 진행했다.

3. 고정 검사 T01~T10

T01~T10은 작업 시작 전에 고정했으며, 검사 ID·입력·기대값은 작업 중 변경하지 않았다.

검사 입력 기대값 최종
T01 템플릿이 없는 상태에서 "여행" 저장 템플릿 1개가 저장된다. PASS
T02 "여행"이 있는 상태에서 "여행" 저장 저장되지 않고 중복 안내가 표시된다. PASS
T03 "맛집" 저장 "맛집" 템플릿이 저장된다. PASS
T04 "맛집"이 있는 상태에서 " 맛집 " 저장 저장되지 않고 중복 안내가 표시된다. PASS
T05 공백만 입력하여 저장 저장되지 않고 이름 입력 오류 안내가 표시된다. PASS
T06 "운동" 저장 "운동"이 저장되고 총 3개가 된다. PASS
T07 "여행"을 "맛집"으로 편집 변경되지 않고 중복 안내가 표시된다. PASS
T08 "여행" 이름을 그대로 유지하며 편집 정상적으로 편집 내용이 저장된다. PASS
T09 "여행"을 " 여행 "으로 변경 변경되지 않고 중복 안내가 표시된다. PASS
T10 "Travel"이 있을 때 "travel" 저장 "travel"이 새 템플릿으로 저장된다. PASS

4. AI A 작업 결과

A는 script.js에 템플릿 이름 중복 방지 로직을 추가했다.

또한 T01~T10을 검증하기 위한 test_templates.js를 생성했다.

그러나 자동 테스트 실행 과정에서 VM을 다시 실행하면서 Identifier 'imageInput' has already been declared 오류가 발생했다.

이후 A가 사용량 제한에 도달하여 작업을 완전히 종료하고 정식 커밋을 남기지는 못했다.

학생은 A의 당시 작업 상태를 보존하기 위해 e31be38 커밋을 생성했다. 이 커밋은 AI A의 커밋이 아니라 학생이 상태를 보존하기 위한 커밋이다.

5. 인수인계

A의 작업 상태를 바탕으로 handoff.md를 작성했다. B는 이전 AI 대화 전문을 전달받지 않고 저장소와 인수인계 문서를 기준으로 작업을 이어갔다.

인수인계 문서에는 다음 7개 항목을 기록했다.

  1. 목표
  2. 현재 상태
  3. 실행 명령
  4. 통과 검사
  5. 남은 문제
  6. 다음 행동
  7. 건드리지 말 것

B는 현재 script.js의 앱 로직이 요구사항을 충족한다고 판단했고, 앱 로직을 변경하지 않고 테스트 하네스 문제를 해결했다.

6. AI B 작업 결과

B는 test_templates.js의 VM 재실행 문제를 수정했다.

또한 편집 검사가 실제 템플릿 수정 버튼 이벤트를 통해 실행되도록 보완했다.

수정 후 동일한 T01~T10을 실행했고, 10개 모두 PASS를 확인했다.

추가로 다음 검사도 통과했다.

  • node --check script.js
  • node --check test_templates.js
  • git diff --check
B는 앱 기능을 다시 수정하는 대신, 실제 문제였던 테스트 하네스만 수정했다.

10. 나의 판단

도구 선택 기준

프로젝트 파일을 직접 읽고 수정하며, 실행과 검증까지 이어서 수행할 수 있는지를 기준으로 선택했다.

AI에게 맡긴 판단

코드 구조 분석, 현재 구현 상태 확인, 테스트 하네스 오류 원인 분석, 필요한 코드 수정과 T01~T10 실행을 AI에게 맡겼다.

내가 직접 판단한 부분

개선 범위와 고정 검사, 시간·요청 상한, 인수인계 범위, 기존 기능을 변경하지 않는 조건을 직접 정했다.

또한 실제 측정값을 임의로 수정하지 않고, A의 요청 수 상한 초과와 B 요청 수 미확인을 그대로 기록했다.

AI 제안을 따르지 않은 부분

확인되지 않은 수치를 추정하여 채우지 않고, 실제로 확인할 수 있는 기록만 결과에 사용했다.
